# Wissensmodell

## Zweck

Das Wissensmodell legt fest, welche Arten von Wissen in der DWD M365 Knowledgebase gefuehrt werden.

## Grundsatz

Die Knowledgebase besteht aus fachlich gleichberechtigten Wissensdomänen. Eine Domäne wird nach ihrem fachlichen Gegenstand bestimmt, nicht nach dem technischen Speicherort ihrer Quellen.

GitHub ist daher eine eigene Wissensdomäne und keine reine Quellenkategorie.

## Wissensarten

| Wissensart | Bedeutung | Beispiel |
|---|---|---|
| Fachwissen | Fachliche Zusammenhaenge und Regeln | Beschaffungsprozess |
| Technisches Wissen | Technische Umsetzung | SharePoint-Architektur |
| Organisationswissen | Aufbau und Zustaendigkeiten | Organisationsstruktur |
| Prozesswissen | Ablaeufe und Verantwortlichkeiten | Genehmigungsworkflow |
| Architekturentscheidung | Verbindliche technische Entscheidung | Berechtigungsmodell |
| Standard | Verbindliche Vorgabe | Namenskonvention |
| Pattern | Wiederverwendbares Loesungsmuster | Power Automate Fehlerbehandlung |
| HowTo | Konkrete Handlungsanleitung | Repository synchronisieren |
| FAQ | Frage und belastbare Antwort | Wo liegt die zentrale Liste? |
| Referenz | Nachschlageinformation | Graph-Endpunkt |
| Projektnachweis | Projektbezogener Stand oder Nachweis | Projektentscheidung |

## Verbindlichkeit

- Entwurf
- In_Pruefung
- Freigegeben
- Verbindlich
- Veraltet
- Ersetzt

## Primaerquelle

Jedes relevante Wissensobjekt soll genau eine fachliche Primaerquelle besitzen. Andere Bereiche referenzieren diese Quelle, statt konkurrierende Kopien zu pflegen.
